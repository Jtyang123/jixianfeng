# 赛题一 + OKC + 急先锋 项目白皮书

## 一、项目概述

### 1.1 项目背景

自然灾害、公共卫生事件和大型公共活动保障都具有“时间紧、约束多、资源分散、责任链长”的特征。传统应急资源调度通常依赖表格、电话和人工经验：物资名称与单位不统一，库存、车辆、道路和安置点信息分散，调度方案缺少独立核验，现场条件变化后也难以快速重算。生成方案的人同时批准方案，还容易形成确认偏差。

急先锋面向园区、学校、医院、社区、物流仓储企业和应急演练服务机构，提供可私有化部署的应急资源调度推演与预案生成平台。系统把复杂任务拆分为需求研判、资源匹配、独立核验和方案交付四个角色，以确定性工具计算库存、路线、载重、时效和成本，以 LLM Planner 负责任务计划与重规划，以人工审批承担最终责任。

### 1.2 应用范围

- 应急演练与预案编制：使用内部物资、仓库、车辆、路线和安置点数据生成不同灾害等级下的调度草案。
- 园区、学校、医院和社区保障：发现资源缺口、道路依赖、运力不足和时效风险。
- 物流与仓储企业：在授权数据范围内验证跨仓调拨、车辆趟次和交付路径。
- 培训与竞赛：展示多智能体编排、独立核验、自循环、调度、RAG、A2A 和可复现运行。

当前版本使用演练数据，不接入真实灾害自动发现、真实库存控制或车辆自动派遣，不替代现场指挥人员。

### 1.3 核心优势

1. **确定性安全内核**：库存、路线、载重、时效、成本和核验结论由确定性工具计算，LLM 不能修改硬规则。
2. **生成与核验分离**：A03 独立核验角色不读取生成角色内部推理，只依据原始数据和规则给出通过、退回或转人工。
3. **可执行的 ReAct 编排**：Planner 负责选择工具、决定顺序和触发重规划，数据读取步骤按计划确定性推进，减少无谓 LLM 调用。
4. **轻量重规划**：核验失败后复用已完成的 demand 和数据读取结果，只重跑 generate / verify / delivery，最新实测单轮约 9.18 秒。
5. **全链路可追溯**：运行事件、工具调用、LLM 调用、调度明细、阶段耗时、A2A 消息、记忆和审批均进入审计。
6. **断网可演示**：AgentArts、LLM 或外部地图不可用时，系统自动回退本地确定性流程。

## 二、解决方案

### 2.1 总体架构

平台采用五层架构：

- 交互层：Vue 3 调度工作台、地图态势、多方案比较、Agent 运行轨、运行详情和人工审批。
- API 层：FastAPI、SSE 事件、库存快照、审计、报告导出和 AgentArts Adapter。
- 编排与调度层：运行时选择、ReAct Planner、DAG 工作流、条件分支、自循环、运行队列和能力画像调度。
- Agent 与工具层：A01 需求、A02 匹配、A03 核验、A04 交付，以及库存、路线、车辆、知识检索和规则工具。
- 数据层：PostgreSQL / SQLite、物资主数据、库存快照、路线、运行事件、证据和记忆。

### 2.2 三档互斥运行时

同一次运行只选择一条主推理链：

| 配置 | 运行时 | 核心四角色 | Planner | AgentArts |
| --- | --- | --- | --- | --- |
| `LLM_ENABLED=true` | `llm-planner` | 本地确定性工具 | 有 | 仅参与 post_verification 扩展审查 |
| `LLM_ENABLED=false`、`AGENTARTS_ENABLED=true` | `agentarts` | 云端 `/invocations` | 无 | 四角色云端调用 |
| `LLM_ENABLED=false`、`AGENTARTS_ENABLED=false` | `local` | 全本地 | 无 | 不调用 |

### 2.3 核心功能

- 物资库、库存快照、仓库、车辆、路线、安置点和事件管理。
- 多目标方案生成：时效优先、成本优先和韧性均衡。
- 道路封闭、库存缺口、车辆不足、时效和需求覆盖核验。
- 结构化退回：只回传问题代码、证据和修复要求。
- ReAct Planner：初始计划、工具调用、结果判断和重规划。
- 轻量重规划：只回传 blocker、required fixes 和历史经验，仅重跑方案生成、核验与交付。
- A2A 请求 / 应答、跨运行记忆和修复经验复用。
- SSE 实时事件、阶段耗时、调度明细和人工审批。
- 工作流设计器、动态 Agent 注册、版本切换和模板库。

### 2.4 技术内容

库存和路线等硬约束由规则引擎计算；LLM 输出结构化 JSON，并由后端校验、补齐和限制在安全策略集合内。知识库当前使用领域同义词 + BM25 + 哈希词袋向量，完全离线运行，不是语义模型；配置 `EMBEDDING_PROVIDER=remote + base_url + model + api_key` 即可切换语义检索。工具通过注册表执行，支持 HTTP API、MCP JSON-RPC 和 Function Calling 风格 schema。

## 三、应用成效

### 3.1 运行效果

最新 Planner run `RUN-20261114-210325-F769`：

- 状态：`awaiting_approval`
- 两轮闭环，最终 `final_verification.verdict=pass`
- 初始计划 8 步，实际执行 10 步，重规划 1 次
- LLM 阶段：`plan=1`、`decide=1`、`replan=1`
- 单轮总耗时：约 9.18 秒
- 交付包状态：`ready`

AgentArts 四端点探活 4/4 HTTP 200，在线率 100%。在线延迟存在波动，因此平台将 AgentArts 定位为可替换的云端证据和扩展审查能力，而不是默认主链路。

### 3.2 质量与可复现性

- 后端自动化测试：137 项通过，3 项 PostgreSQL 环境跳过；PG CI 共 140 项。
- 前端自动化测试：9 项通过（5 个测试文件），生产构建成功。
- 确定性内核 benchmark：6 个场景，1/5/10/20 四档均使用 18 个固定样本，共 72 个样本。
- 多 Agent 安全结果率 100%，单 Agent 贪心基线安全提案率 66.67%。
- 工具调用计数与明细一致：336 / 336。
- 基准范围为 `deterministic-core in-process; excludes LLM planner, HTTP, queue and DB IO`，不把函数级计算数据冒充端到端在线延迟。

### 3.3 具体应用案例

暴雨洪涝演练中，首轮方案因 4 条道路封闭被独立核验退回。系统生成结构化修复要求，Planner 复用需求和数据读取结果，只重新生成方案、核验和交付。第二轮排除封闭路线并改用备用通道后通过核验，评分恢复至 100，随后进入人工审批和库存预留。

该结果证明系统能识别错误方案、拒绝假通过、解释退回原因并在安全约束内重新收敛。

## 四、商业模式

### 4.1 推广模式

- **私有化部署**：面向园区、学校、医院、社区和物流企业，按部署规模和模块授权收费。
- **SaaS 订阅**：提供演练项目管理、知识库、Agent 编排、运行审计和报告服务。
- **培训与咨询**：围绕应急预案数字化、指标体系、演练复盘和数据治理提供实施服务。
- **行业模板**：沉淀不同灾害、行业和组织类型的 Agent 契约、规则库和核验模板。

### 4.2 市场空间

目标客户包括产业园区、教育机构、医疗机构、社区街道、物流仓储企业和应急演练服务机构。初期以内部演练和预案编制为切入点，后续接入 WMS/ERP、车队定位、地图路况和指挥平台。商业模式重点不是一次性演示，而是年度演练、数据维护、规则升级和审计服务形成持续收入。

### 4.3 生态运作

平台保持 AgentArts、LLM、地图、物流接口和 MCP 工具的开放适配。合作伙伴可以提供行业规则、车辆资源、仓储数据、地图与应急服务；平台负责编排、核验、审计和交付。所有外部工具必须经过白名单和安全校验，AI 不能绕过人工审批。
