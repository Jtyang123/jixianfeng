## 一、平台级运行队列

正式服务同时提交 3 个运行，平台并发上限为 2：

| 运行 | 开始时间 | 排队等待 | 结果 |
|---|---|---:|---|
| `RUN-20261108-232008-99CD` | 23:20:08.904 | 52.96 ms | awaiting_approval |
| `RUN-20261108-232008-8CEA` | 23:20:09.185 | 307.52 ms | awaiting_approval |
| `RUN-20261108-232009-6747` | 23:20:41.021 | 31,584.24 ms | awaiting_approval |

验收结论：

- 前两个任务由两个 Worker 并行领取；
- 第三个任务在并发上限已满时真实排队，而不是同时启动第三条流水线；
- 三个任务均只执行 1 次成功尝试，无失败和重复提交；
- `GET /api/queue/metrics` 返回 `scheduler_started=true`、并发上限 2、运行中 0、队列中 0；
- 租约过期恢复、幂等 `Idempotency-Key` 和最大尝试次数由自动化测试覆盖；
- PostgreSQL 使用 `FOR UPDATE SKIP LOCKED`，SQLite 使用条件更新防止重复领取；
- 两个独立操作系统进程共享同一 SQLite 数据库的实测：30 个任务、墙钟 0.5563 秒、吞吐 53.92 次/秒、P95 领取到完成 19.25 ms、峰值并发 2；
- 任务无重复、无遗漏，证明多进程领取协议有效；
- 真实 PostgreSQL 18.6 已执行迁移、`FOR UPDATE SKIP LOCKED` 和并发预留测试，3 项集成测试通过；
- PostgreSQL 测试证明：一个事务锁住最高优先级队首时，第二个 Worker 会跳过该行领取下一任务；
- PostgreSQL 并发审批同一批库存时，恰好一个成功、一个冲突；
- GitHub Actions 已配置 `postgres:18` service，后续 CI 会持续执行 PG 集成测试，不再只依赖文档声明。

## 五、知识库与引用定位

实机上传 Markdown 后检索“道路封闭备用通道”：

- 默认检索模式：`offline-lexical-hash+bm25+deterministic-rerank`
- 默认环境明确标注 `semantic_retrieval=false`，不宣称已经启用语义检索
- 当前离线 embedding：`domain-hash-v1`，256 维
- 配置 OpenAI-compatible embedding 后才标记为 `remote-semantic`；失败自动回退词法哈希模式
- 重排是确定性规则重排，不把规则重排宣称为模型 rerank
- 返回引用：`章节：道路封闭处置规则`，字符区间 `0–36`
- PDF 上传按页保存 `page_no`；文档段落保存章节与字符起止位置
- `KNOWLEDGE_CHECK` 工具结果会注入后续匹配、核验与交付上下文，不再是装饰节点
- 文档入库使用规范化内容 SHA-256 去重，重复上传返回原文档 ID，不重复生成 chunk
- 检索证据标记为 `untrusted_document`，文档内指令不得执行
- 命中提示注入模式时，证据被 `<<UNTRUSTED_DOCUMENT_DATA>>` 边界包裹并记录 `injection_flags`
- LLM 与 AgentArts 只接收隔离后的证据，文档正文不能成为系统指令

## 六、AI 决策路径

- AgentArts 四个核心 Agent 均返回 HTTP 200，覆盖 `4/4`；
- 需求优先级支持相邻 P0–P3 调整；
- 匹配权重支持 speed/cost/risk 建议，与用户权重各占 50%，只影响已核验方案排序；
- 修复策略仍只能从 `allowed_rework_policies` 选择；
- 核验硬规则结论不可被模型覆盖；
- 决策矩阵共 7 项，逐项记录来源、安全边界、降级策略和本地确定性等价能力；
- 当前内部 LLM 未启用时，AgentArts 仍承担需求、策略与推荐决策，确定性内核保持可运行；
- 答辩口径明确为“LLM 在确定性安全边界内做优先级、权重、修复策略和推荐”，不宣称模型负责全部方案计算与核验判断。
